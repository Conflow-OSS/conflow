𝗧𝗛𝗘 𝗔𝗥𝗖𝗛𝗜𝗧𝗘𝗖𝗧𝗨𝗥𝗘

 • I figured they'd probably have a control plane API which the web interface communicates with. Whenever a new Agent browser session is requested, it schedules a job on Google Cloud Run Jobs (which has a very generous free tier btw), then stores the session metadata in Cloud SQL or Cloud Firestore

 • These jobs run in an isolated environment with the open source tool running in each job container. This way, sessions cannot interfere with each other. 

 • Also, it provides the jobs with one-way access to the internet (they can access the internet, but the internet can't access them) by connecting them to the internal VPC and using a NAT Gateway + Cloud Router.

This way, the Browser sessions can connect to the LLMs via their public APIs.

 • Any files generated by a session will be stored in a public Google Cloud Storage bucket.

---
The architecture here might not be accurate, but it kinda makes sense (to me at least :)...
